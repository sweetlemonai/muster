# mu-152 Persian (fa) CLI help review

- **Who:** an independent reviewer agent (Claude) that didn't write these translations.
- **When:** 2026-10-15, on `.claude/work/mu-152/help/help-fa.json` against `help-en.json` (209 strings each).
- **Against:** `TRANSLATE.md` in this folder and `docs/i18n/glossary-fa.md` (which wins: lease = مهلت, not
  TRANSLATE.md's «مهلت اجاره»).
- **Method:** a script checked the mechanical rules on all 209 strings: same key set, no bidi controls
  (U+200E/F, U+202A–E, U+2066–9, U+061C), no Persian or Arabic digits, no Arabic ي/ك, every
  string's first strong letter Persian, every `what` with a first sentence ending in ". ", Latin
  `? ; ,` after Persian letters, می/نمی without ZWNJ, a space before ها, الان, the Persian
  spelling of Git used for "gate", and every literal (`--flag`, `$ENV`, numbers, `mu-N`, file names)
  in the English present in the Persian. Then I read every string against its English source.
  Where the meaning was unclear, I checked the code (`cli.rs:5453` for the list filter, `lessons.rs:383`
  for the lesson cap) and the app's fa labels (`shell.json`, `board.json`) for the UI words the
  help quotes. Strings that are fine aren't listed.

**Verdict:** this is a good translation. The mechanical checks all pass: no bidi controls, Latin
digits only, no Arabic letters, every string starts with a Persian word, every `what` has its
summary sentence, and every literal is kept. Glossary words are used consistently for claim,
check-in, heartbeat, lease, stages, owner, session, holder, slot, role, shaping, lesson,
finding and gate. **3 must-fix** strings change the meaning: the builder rule in `pass`, the
lesson-expiry rule, and "agents build only tasks" in `new`. **14 should-fix** strings use the
wrong term or are unclear. The main problems are "write-up" rendered as شرح, which collides
with شرح کار (brief); "dispute" rendered as رد; the claim noun written as a bare برداشتن;
برنامه for "app"; and سؤال for "question". There are also **24 nits**, mostly the same English
worded two ways. Each finding below has the full replacement string. When a key has several
problems, they're merged into one finding, so each replacement can be pasted as it is. Every
replacement was generated from the current string and re-checked against the same mechanical
rules.

## Findings

### 1. `cmd.new.what` (must)

- The clause «ایجنت‌ها فقط تسک می‌سازند» reads "agents only create tasks". The English is "agents build only tasks" (they never build a goal or a feature), and in the help for `muster new`, where the first sentence uses بسازید for "create", the reader takes it as a rule about creating. Use پیاده‌سازی for "build" here.
- nit: "a screen state with a baseline" is «خط مبنا» here and «خط پایه» in `cmd.file.what` for the same sentence. Kept خط مبنا here; the file.what finding aligns to it.
- Changes: «ایجنت‌ها فقط تسک می‌سازند» → «ایجنت‌ها فقط تسک‌ها را پیاده‌سازی می‌کنند»
- Replacement:

```text
تسکی در «آماده» بسازید. شناسه‌اش به ترتیب و زیر قفل صف گرفته می‌شود و در لاگ به نام شما ثبت می‌شود. با --level یک هدف است (یک نتیجه، می‌تواند سررسید داشته باشد) یا یک قابلیت (تسک‌ها را گروه می‌کند)؛ ایجنت‌ها فقط تسک‌ها را پیاده‌سازی می‌کنند. با --human تسک خود مالک برای انجام است (for: human): فقط مالک آن را می‌سازد و ایجنت‌ها هرگز آن را برنمی‌دارند؛ ایجنتی که به کاری برمی‌خورد که فقط از مالک برمی‌آید، آن را با muster add پیشنهاد می‌کند. معیاری که فقط مالک تأییدش می‌کند (— verify: owner) رد می‌شود مگر اینکه خود مالک تسک را بسازد (--as owner): آن را اثبات‌پذیر کنید (یک تست، یک اندازه‌گیری، یک وضعیت صفحه با خط مبنا)، یا آن را بررسی گام‌به‌گام کنید (qa: walkthrough). ایده‌ای که هنوز تسک نیست به جای آن به بک‌لاگ می‌رود (muster add).
```

### 2. `cmd.pass.what` (must)

- Meaning: "the same --as label, in the same session or with none" means the same label with the same session or with no session stamp. «یا بدون برچسب» says "or with no label", which inverts the rule (the label is the thing that must match).
- Readability: the human task path «مسیر برای انجام (آماده) ← در حال انجام (در حال ساخت) ← انجام شد را می‌رود» has no quotes, so «مسیر برای انجام» reads as "the path for doing". Quote the stage words.
- Term: "write-up" is «شرح تسک» here, but شرح کار is "brief" in the glossary and in this file. `cmd.edit.what` (the write-up's own command) uses نوشته; use «نوشته‌ی تسک».
- Term: "the app's Pass" is «در برنامه»; every other string says اپ.
- Term: "A task made with muster start" is «ساخته شده», which collides with "built" (سازنده). `cmd.move.what` already says «با muster start شروع شده».
- Literal: ("— verify: owner") keeps ASCII quotes; `cmd.tick.what` has «— verify: owner». Use « ».
- nit: «در فاصله‌ای که از main جدا شده» for "since it left main" is stiff.
- Changes: «در همان نشست یا بدون برچسب» → «در همان نشست یا بدون نشست»; «مسیر برای انجام (آماده) ← در حال انجام (در حال ساخت) ← انجام شد را می‌رود» → «مسیر «برای انجام» («آماده») ← «در حال انجام» («در حال ساخت») ← «انجام شد» را طی می‌کند»; «باقی‌مانده در شرح تسک» → «باقی‌مانده در نوشته‌ی تسک»; ««فرستادن» در برنامه» → ««فرستادن» در اپ»; «تسکی که با muster start ساخته شده،» → «تسکی که با muster start شروع شده،»; «("— verify: owner")» → «(«— verify: owner»)»; «(کامیت‌شده، در فاصله‌ای که از main جدا شده)» → «(کامیت‌شده، از وقتی از main جدا شده)»

```text

حوزه، هرکدام با covers: <globs>)، تسکی که touches: آن با covers: یک صفحه هم‌پوشانی دارد باید آن صفحه را روی شاخه‌اش تغییر دهد (کامیت‌شده، از وقتی از main جدا شده)، یا با --now-unchanged "<why>" بگوید چرا هنوز برقرار است (یک خط، 500 نویسه)؛ در هر دو حال لاگ آن صفحه‌ها را نام می‌برد. در غیر این صورت رد می‌شود و صفحه را نام می‌برد. تسک بدون touches:، تسکی که هیچ صفحه‌ای پوشش نمی‌دهد و پروژه‌ی بدون هم به تیک خوردن آن‌ها نیاز دارد (muster tick). تسک انسانی (تسک خود مالک) مسیر «برای انجام» («آماده») ← «در حال انجام» («در حال ساخت») ← «انجام شد» را طی می‌کند و فقط مالک آن را می‌فرستد: بدون خط دروازه، بدون «در حال تست»، بدون «بررسی شما». رد می‌شود وقتی مسدود است، وقتی کس دیگری آن را در دست دارد، و برای ورود به «در حال ساخت» (آماده ← در حال ساخت، یا «شروع» از سوی مالک) تا وقتی تسکی که به آن وابسته است هنوز ادغام نشده، همان‌طور که claim رد می‌شود. تسکی که با muster start شروع شده، وقتی از «در حال تست» فرستاده شود ادغام می‌شود، به شرطی که بازبینی ثبت‌شده‌اش در نوک شاخه‌اش تمیز باشد (muster review) و هر رکورد دروازه‌ای که لازم دارد آنجا سبز باشد (muster gates: معیارها برای تسکی که پس از آمدن رکوردهای دروازه شروع شده، QA بصری وقتی qa: تنظیم شده؛ needs-walkthrough آن را نگه نمی‌دارد) (مالک می‌تواند بدون آن‌ها ادغام کند و گزارش این را می‌گوید؛ کامیتی که در انتظار ادغامی دیگر یا هنگام اجرای دروازه‌اش ساخته شود آن را ادغام‌نشده متوقف می‌کند)، به ترتیب، و در نخستین شکست می‌ایستد: در هر مخزن worktree آن (muster projects set <name> gate؛ قرمز آن را با خط دروازه برمی‌گرداند)، و دوباره اگر main در این میان جلو رفت (حداکثر دو بار، سپس می‌ایستد: main مدام جلو می‌رود)؛ fast-forward کردن main می‌ایستد)؛ حذف worktree (هرگز worktree اجراکننده‌ای که با start --here ساخته شده) و پاک کردن شاخه، و نسخه‌ی origin آن فقط وقتی همان کامیت است؛ ثبت ادغام (کامیت و یک گزارش: خط دروازه، بازبینی، رکوردهای ## Findings

### 1. `list.pausedSince` (should)

- «متوقف از» is a clipped participle; board.json writes «متوقف‌شده از {{at}}» (`pause.wasSince`), as mu-147's review (R2) settled. The CLI's list row should read like the board.
- Changes: «[متوقف از» → «[متوقف‌شده از»
- Replacement:

```text
[متوقف‌شده از {{since}}]
```

### 2. `said.nextReview` (should)

- "the review of record" is «بازبینی رسمی» here; the help now says «بازبینی ثبت‌شده» everywhere (review-1 finding 8).
- Changes: «بازبینی رسمی» → «بازبینی ثبت‌شده»
- Replacement:

```text
بعدی: بازبینی ثبت‌شده، توسط نشستی که آن را نساخته است: muster review {{key}} شرح کارش را چاپ می‌کند
```

### 3. `start.pickedUp` (should)

- "picked up {{key}}" (a task started before, picked up again in its worktree: `cmd.start.what`) is «دوباره در دست گرفته شد». «در دست گرفتن» is the glossary's word for take over (a claim from another session), which is a different event with its own message (`said.tookTask`). «از سر گرفته شد» says resumed work without that clash.
- Changes: «دوباره در دست گرفته شد:» → «از سر گرفته شد:»
- Replacement:

```text
از سر گرفته شد: {{key}} در {{project}} ({{root}})
```

### 4. `said.finding` (should)

- Word order: «یافته‌ی {{finding}} مالک» reads "finding R3 of the owner" with the id between the noun and its owner; the help says «یافته‌ی مالک» as one term. Put the id after it.
- "fix" a finding is رفع in the help (`review`, `return`); use it here too.
- Changes: «یافته‌ی {{finding}} مالک، تا سازنده آن را درست کند» → «یافته‌ی مالک {{finding}}، تا سازنده آن را رفع کند»
- Replacement:

```text
تسک {{key}}: یافته‌ی مالک {{finding}}، تا سازنده آن را رفع کند یا به آن اعتراض کند؛ اول صف
```
